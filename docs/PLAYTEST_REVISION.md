# INHERITANCE — 플레이 테스트 기반 개선 요청

게임: https://gnfls8-ops.github.io/Inheritance/  
저장소: https://github.com/gnfls8-ops/Inheritance

이번 작업은 현재 구현된 플레이 구조를 개선하는 작업이다. 아래 요구사항을 구현하고 검증해줘. 새로운 시대나 대규모 콘텐츠 추가보다 핵심 정체성과 플레이 경험을 우선한다.

## 1. 최우선 원칙

INHERITANCE의 핵심은 다음과 같다.

> 한 인간으로 살아가며 남긴 선택과 지식이 다른 인간을 통해 역사로 이어진다.

- 플레이어는 한 시점에 한 인간만 조작한다.
- 다른 인간은 독립적인 자율 NPC다.
- NPC 클릭과 목록 선택은 관찰 대상만 변경한다.
- 다른 NPC에게 직접 행동 명령을 내릴 수 없다.
- 협력은 부탁·대화·설득·전승을 통해 간접적으로 이루어진다.
- **현재 플레이어가 사망한 뒤 생애 결산을 거쳐야 다른 인간으로 계승할 수 있다.**

현재 구현된 플레이어 신분·관찰 대상 분리와 시뮬레이션의 명령 권한 검사는 유지한다.

## 2. P0 — 생존 중 캐릭터 변경 차단

### 현재 문제

‘이 삶 마무리하기’를 이용하면 현재 인간이 살아 있어도 직접 조작을 종료하고 다른 인간으로 변경할 수 있다. 이는 사망 이후에만 계승한다는 원칙과 충돌한다.

### 수정 요청

- 일반 플레이에서 ‘이 삶 마무리하기’를 제거한다.
- 시뮬레이션에서도 생존 중 은퇴를 통한 계승 전환을 차단한다.
- 역사 모드는 플레이어 사망과 결산 확인 이후에 사용할 수 있게 한다.
- 역사 모드 진행 중 다음 인간을 선택하면 생활 모드·일시정지로 진입한다.
- 생애 모드와 중요 사건 자동 정지는 유지한다.
- 테스트 편의를 위한 강제 종료가 필요하면 일반 플레이 UI와 분리한다.

### 완료 기준

- 살아 있는 동안 다른 인간으로 변경할 수 없다.
- NPC를 관찰해도 플레이어 신분은 유지된다.
- 사망 → 자동 정지 → 생애 결산 → 결산 확인 → 역사 진행 또는 계승자 선택 순서가 작동한다.
- 계승 후 세계의 인구·자원·관계·지식·문화가 초기화되지 않는다.

## 3. P1 — 인물의 나이와 생존 상태 표시

### 현재 문제

계승 후보의 나이를 알 수 없으며, 사망자를 관찰해도 건강·행동 정보가 살아 있는 인물처럼 표시될 수 있다.

### 수정 요청

- 플레이어와 NPC 패널에 나이·생존 상태를 표시한다.
- 사망자는 사망일·향년·사망 원인을 표시한다.
- 사망자의 욕구·행동 정보는 현재 상태로 오인되지 않게 ‘사망 당시 정보’로 구분한다.
- 관찰 목록에서 생존자와 사망자를 구분한다.
- 계승 후보에 이름·나이·주요 기질·보유 지식을 표시한다.
- 노령 위기에는 ‘80세까지 얼마 남지 않음’처럼 실제 이유를 설명한다.
- 계승 대기 중에는 ‘현재 플레이어’ 대신 ‘이전 삶’과 ‘계승 대기’ 상태를 명확히 표시한다.

### 완료 기준

- 계승 전에 후보의 나이와 특징을 알 수 있다.
- 사망자를 생존자로 오인하지 않는다.
- 건강이 높아도 노령으로 사망할 수 있다는 규칙을 이해할 수 있다.

## 4. P1 — 시간 모드별 인구 규칙 일관성

### 현재 문제

현재 코드에서 출생은 역사 모드에 구현돼 있다. 생활·생애로 진행하는 경우와 역사로 진행하는 경우에 인구 재생산 규칙이 달라진다.

### 수정 요청

- 출생 자격·주기·확률·인구 제한을 공통 인구 시스템으로 분리한다.
- 생활·생애·역사 모든 모드에서 출생·노화·사망이 발생하도록 한다.
- 역사 모드의 이동·접촉 계산은 집계 방식으로 유지할 수 있다.
- 생활과 생애는 동일 일수·명령 기준으로 같은 결과를 유지한다.
- 역사 모드는 상세 계산의 근사임을 UI에서 짧게 설명한다.
- 사건 확률과 쿨다운은 현실 시간이 아닌 게임 내 날짜를 기준으로 유지한다.
- 긴 시간 묶음 안에서도 중요 사건과 플레이어 사망 시 즉시 중단한다.

### 완료 기준

- 생애 모드에서도 공동체에 출생이 발생할 수 있다.
- 모드 전환으로 인물·자원·지식이 재생성되지 않는다.
- 인구와 자원이 음수가 되지 않는다.
- 빠른 진행이 사망이나 결산을 건너뛰지 않는다.

## 5. P1 — 대화 사건을 실제 상호작용으로 연결

### 현재 문제

‘새로운 대화의 기회’가 자동 정지는 시키지만, 구체적인 상대와 상황 없이 교류를 권하는 안내에 가깝다.

### 수정 요청

- 사건에 실제 살아 있는 상대 NPC를 연결한다.
- 사건 발생 이유와 상대의 상황을 짧게 표시한다.
- 최소 선택지는 ‘대화하기’, ‘식량 나눔 부탁’, ‘지금은 지나가기’로 구성한다.
- 지식 전승은 플레이어가 알고 있는 기술과 상대의 보유 여부에 따라 제공한다.
- 거리 조건을 만족하지 않으면 접근 행동으로 연결하거나, 지금 불가능한 이유를 표시한다.
- NPC는 욕구·기질·관계에 따라 수락하거나 거절한다.
- 선택의 결과를 관계·욕구·식량·지식 등 실제 상태에 반영한다.
- 일시정지 상태에서 부탁을 무제한 반복해 성공만 얻는 문제를 막기 위해 요청 비용 또는 게임 내 쿨다운을 적용한다.

### 완료 기준

- 누구와 왜 대화하는 사건인지 알 수 있다.
- 선택에 따른 실제 결과가 존재한다.
- 상대가 사망하거나 조건이 바뀌어도 진행이 막히지 않는다.

## 6. P1 — 행동 결과를 즉시 전달

### 현재 문제

행동과 기술 결과가 오른쪽 패널 하단이나 페이지 아래 기록에 있어 놓치기 쉽다.

### 수정 요청

- 플레이어 관련 행동 결과를 지도 근처의 고정된 알림 영역에 표시한다.
- 명령의 예약·진행·완료·실패·취소를 구분한다.
- 채집량, 피로 회복량, 식량 소비, 관계 변화 등 주요 결과를 표시한다.
- 실험의 비용과 실패 위험을 실행 전에 안내한다.
- 실험 실패 시 건강 감소가 있다면 이를 설명하고 결과에도 표시한다.
- 발견·전승·지식 소실은 일반 행동보다 강조한다.
- 시간이 이미 흐르고 있을 때 ‘시간을 재생하세요’라는 안내를 표시하지 않는다.
- 알림은 요약하고 상세 기록은 보존해 화면을 과도하게 가리지 않는다.

### 완료 기준

- 스크롤하지 않아도 방금 지시한 행동의 결과를 알 수 있다.
- 명령을 내린 것과 실제 완료된 것을 구분할 수 있다.

## 7. P1 — 개인 연대기와 지식 전승 경로

### 현재 문제

후대에 지식이 남는 결과는 작동하지만, 누가 누구에게 전했는지와 이전 인간의 기여를 파악하기 어렵다. 생애 결산도 지식 목록과 관계 인원 수 중심이다.

### 수정 요청

개인 연대기에 다음을 기록한다.

- 직접 발견한 기술
- 다른 인간에게 배운 기술
- 지식을 전한 상대
- 중요한 도움·거절·관계 사건
- 사망과 주요 세계 사건

지식 전승 기록에는 다음을 포함한다.

- 기술
- 전달자와 수용자
- 날짜
- 전달 방식: 직접 전승·교류·역사 집계 등

역사 모드의 자동 전승도 같은 기록 체계를 사용한다.

생애 결산에는 다음을 표시한다.

- 플레이한 기간과 사망 원인
- 직접 발견·습득한 지식
- 지식을 전한 사람
- 중요한 관계
- 결산 시점에 세계에 남아 있는 영향

이미 소실된 지식이나 이후의 결과를 추측해서 성취로 표시하지 않는다.

### 완료 기준

- 아라가 발견한 불 관리가 다른 사람에게 이어진 경로를 확인할 수 있다.
- 이전 인물 데이터가 정리돼도 기록의 이름과 사건 의미가 보존된다.
- 단순한 보유 지식과 직접 발견한 업적을 구분한다.

## 8. P1 — 기술의 생활 변화 표현

최종 아트 제작에 앞서 임시 그래픽으로 다음 차이를 표현한다.

- 불 관리: 불을 사용하는 생활 행동
- 석기 제작: 도구를 사용하는 채집 행동
- 식량 저장: 저장 행동이나 저장물 표현

단, 개인이 기술을 발견했다고 공동체 전체가 즉시 같은 생활양식으로 바뀌면 안 된다. 개인 보유와 공동체 정착 단계를 구분한다.

### 완료 기준

- 기술 카드의 숫자를 읽지 않아도 변화가 보인다.
- 발견·개인 사용·전승·공동체 정착이 구별된다.
- 표현이 실제 효과 적용 대상과 일치한다.

## 9. P2 — 확인된 표시 문제 수정

- 상단 날짜·사건 날짜·사망일·결산 날짜의 기준을 통일한다.
- 경과 일수와 달력상의 날짜를 구분한다.
- 장기 진행 후 과거 행동 기록의 인물 이름이 사라지지 않게 한다.
- ‘해솔와’, ‘후대 63와’ 등의 조사 오류를 수정한다.
- 기술의 ‘미발견’, ‘개인 미습득’, ‘과거 발견 후 소실’을 구분한다.
- 시대·그래픽·저장 형식과 별개로 배포 빌드의 버전 또는 커밋을 표시한다.
- README의 오래된 제한 설명과 최신 구현 설명을 정리해 모순을 제거한다.

## 10. 구현 및 검증 순서

다음 순서로 작은 변경 단위로 진행한다.

1. 조작·사망·계승 규칙 확정 및 권한 검사
2. 나이·생존·사망·계승 후보 UI
3. 공통 인구 시스템과 시간 모드 검증
4. 행동 결과 알림과 대화 사건
5. 개인 연대기·전승 기록·생애 결산
6. 기술 생활 표현과 표시 오류 수정

의미 있는 자동 테스트를 추가하거나 갱신한다.

- 생존 중 계승 차단
- NPC 직접 명령 거절
- 사망과 중요 사건에서 시간 묶음 중단
- 모든 모드의 인구 규칙
- 생활·생애의 동일 일수 결과
- 기록 대상 인물 정리 이후 기록 보존
- 저장·복원 후 신분·사건·인구·전승 이력 유지

실제 브라우저에서도 최초 선택 → NPC 관찰 → 부탁 → 기술 발견·전승 → 생애 진행 → 사망 → 결산 → 역사 진행 → 계승 → 저장·복원을 확인한다.

기존 v2 저장 호환성을 고려하고, 데이터 구조를 변경하면 필요한 마이그레이션과 검증을 추가한다. 손상된 저장 파일이 현재 세계를 덮어쓰지 않게 한다.

완료 보고에는 다음을 구분해 작성한다.

- 구현한 변경
- 자동 테스트 결과
- 실제 플레이로 확인한 결과
- 코드로만 확인한 항목
- 미구현·미검증 항목

이번 개선의 목표는 **시간을 빠르게 보내는 기능의 확대가 아니라, 한 인간의 삶과 그가 남긴 영향을 플레이어가 이해하고 기억하게 만드는 것**이다.
